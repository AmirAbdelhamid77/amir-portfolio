# رؤية ما بعد التسليم — عقود تجعل Hansa قابلة للإضافة

ملحق إلزامي لـ[وثيقة التسليم](AGENT_HANDOFF_AR.md). الحالة: تصميم للعقود، وليس تطبيقًا لها. الأسماء أدناه مقترحة؛ يُعاد استخدام ما يكافئها في المصدر الحالي بدل إنشاء طبقة مكررة.

## 1. الفكرة التي يجب أن تستمر بعد إعادة التصميم

Home يقدم ثلاث وظائف قابلة للتوسع: **اختيار لحظة، استكشاف معرفة، اتخاذ خطوة تعلم**. يمكن إضافة أنواع محتوى أو طرق دخول مستقبلًا مع الاحتفاظ بهذه البنية، وبنفس لغة التحديد والفتح والعودة والحركة.

KnowledgeDealer موجود بالفعل في `components/knowledge/knowledge-dealer.tsx` ويستقبل cards/reader/callbacks. `lib/knowledge/models.ts` يحضر بطاقات الفكرة ونص القارئ. لذلك نطور العقد بين مصدر البطاقات وعرضها: البداية بطاقات اليوم، ثم مجموعات موضوع أو هدف عندما تُطلب ميزاتها. لا نكتب Dealer آخر لكل مكان يظهر فيه.

هذه هي «رؤية ما بعد»: اليد نفسها تستطيع عرض سياق جديد، وتظل قواعد القراءة والمصدر والمراجعة والتركيز والعودة موحدة. يمكن أن يبدأ المستخدم من Timeline أو Atlas، ويعود إلى المكان الذي فتح منه المجموعة.

## 2. التزام الآن، وتجهيز الآن، وميزة لاحقًا

| القدرة | المطلوب في التسليم الأساسي | ما يجهز بنيويًا | الإضافة اللاحقة عند طلبها |
|---|---|---|---|
| Daily Dealer | فتح اليوم وعرض بطاقاته وقراءته وربطه بالأطلس | فصل source adapter عن العرض والـHome shell | زيادة الإصدارات والأفكار المؤهلة وفق برنامج تحريري |
| Topic Dealer | لا أمر عام جديد مطلوب | طلب سياق وعودة؛ fixture تطوير لموضوع حقيقي لا يظهر للجمهور | اختيار مجموعة موضوعية ونشرها وزر فتحها من الأطلس |
| Goal Dealer | استخدام الأهداف الحالية في الأطلس حسب نطاقها | تمرير سياق هدف دون ربطه بهندسة الورق | جلسة بطاقات متسقة لهدف، بعد تحديد محتواها ومراجعتها |
| مقارنة/تجربة داخل بطاقة | إعادة استخدام تجربة الفكرة الموجودة إن وجدت | renderer صريح قابل لإضافة نوع، مع بديل نصي | تحرير مقارنة أو تجربة جديدة وتحققها العلمي |
| حفظ مجموعة | استعادة حالة الزيارة الحالية | هوية مجموعة ومراجعة ومفتاح جلسة مستقل | حفظ عبر الزيارات وإدارة مجموعات ومخطط ترحيل |
| Atlas مستقل | نفس المستكشف داخل Home | نموذج تنقل وحالة لا يعتمدان على إحداثيات Home | route مستقل عند الحاجة، بنفس البيانات والتفاعل |
| مجال/مصدر إضافي | الفهرس من مصادر محددة ومتحقق منها | metadata قابلة للزيادة وتخطيط لا يفترض العدد8 دائمًا | adapter لمصدر جديد مع مراجعة التصنيف والحقوق |
| علاقات متعددة المجالات | عرض published فقط في النطاق المتاح | فصل الفهرس العام عن الإسقاط العلمي | سياسة مصادر متعددة ومراجعة ونشر علاقات جديدة |
| متابعة شخصية أوسع | قراءة محركات التقدم الموجودة | adapters بقدرات معلنة وunknown صريحة | حفظ اختيارات شخصية؛ أي مزامنة أو حسابات مهمة مستقلة |

الجاهزية لا تعني أزرار Coming soon أو تبويبات فارغة. المسارات غير المنفذة لا تظهر كوظائف متاحة. لا تُحمّل بياناتها أو renderer غير مستخدم في أول صفحة.

## 3. الحدود العملية الخمسة

1. **Home composition:** يحدد المشاهد ويستقبل طلب فتح/انتقال؛ لا يحتوي شروطًا خاصة بـSQL أو Fabric لاختيار صحة المحتوى.
2. **Library index:** يحتفظ بهوية الموارد ومواضعها وروابطها والحد الأدنى من metadata؛ مصدره ملفات الموقع، وليس نسخة جديدة من نصوصها.
3. **Deck resolver:** يفسر سبب الفتح، يرجع للمصدر الأصلي، يتحقق من الأهلية، ثم يحضّر مجموعة صالحة للعرض.
4. **Dealer presentation/session:** يعرض الحزمة/اليد/القارئ، ويدير الاختيار والتركيز والحركة؛ لا يصحح إجابات أو يرقّي حالة مراجعة.
5. **Original learning engines:** تملك التصحيح والجلسات والنتائج والتقدم. Home يقرأ منها، والذهاب للتدريب يمر بعقدها الطبيعي.

يتم التواصل عبر props/callbacks وأنواع محددة، مع reducer محلي إذا ساعد على وضوح الحالات. لا event bus شامل ولا runtime plugin loader ولا كود تنفيذي مأخوذ من JSON. المرجع الواحد لمعنى المجال يبقى في مصدره.

## 4. مراجع الهوية

كل بطاقة تشير إلى مادة فعلية، ولا تجعل معرّفها الجديد بديلًا لمعرّف السؤال أو الدرس:

```ts
// رسم عقد للتصميم، لا كود مطلوب نسخه حرفيًا.
type ContentRef = {
  sourceKind: string;       // عائلة مصدر معروفة في resolver
  originalId: string;       // ID القائم، بدون إعادة ترقيم
  revision?: string;        // من المصدر عند وجوده، لا قيمة مختلقة
};

type ReturnContext = {
  version: 1;
  scene: 'timeline' | 'atlas';
  editionId?: string;
  subjectId?: string;
  topicId?: string;
  selectedResource?: ContentRef;
  ancestorIds?: string[];   // سلسلة محدودة ومتحقق منها
};
```

سجّل أنواع المصدر المسموح بها في التنفيذ الفعلي كاتحاد محدد أو registry صريح، ولا تسمح لقيمة sourceKind أن تستورد ملفًا أو حزمة عشوائيًا. إذا لم تكن للمصدر revision، يمكن استخدام build content fingerprint معلوم لمراقبة التغيير مع توضيح معناه؛ ليس هذا تاريخ مراجعة علمية.

ربط المادة بمفهوم Atlas اختياري ومراجع؛ بعض الموارد موجودة دون مفهوم منشور. الـhref يحتفظ بالanchor/query؛ لا dedup اعتمادًا على pathname وحده. placements المتعددة تشير لنفس ContentRef. revision تغير المحتوى ولا تمحو هوية المستخدم أو إجابة سابقة.

## 5. طلب فتح مجموعة البطاقات

```ts
// الحالات future لا تصبح قدرات عامة بمجرد وجودها في وثيقة التصميم.
type DeckOrigin =
  | { kind: 'daily'; editionId: string }
  | { kind: 'topic'; subjectId: string; topicId: string }
  | { kind: 'goal'; goalId: string };

type DeckRequest = {
  origin: DeckOrigin;
  returnContext: ReturnContext;
};
```

المسار الحقيقي في الإصدار الأول daily. يمكن أن يكون topic adapter صغيرًا لاختبار التوسعة في بيئة التطوير، دون واجهة جمهور أو إطلاق ميزة جلسات موضوعية كاملة. goal يظل وصفًا للعقد حتى يتوفر محتوى وطلب تنفيذ مناسب؛ في التنفيذ استعمل فقط variants المنفذة أو تعامل صراحة مع unsupported.

الطلب لا يحمل إجابات سرية أو flags مثل `ignoreReview=true`. لا تؤخذ أهليته من query المستخدم. resolver يعود بنتيجة discriminated مثل ready/empty/unavailable/unsupported/error، ورسالة/بديل مناسب، بدل رمي استثناء يترك الحوار فارغًا.

لا يتوقف فتح الحوار على انتهاء animation. وإذا احتاجت مجموعة إلى chunk static، يظهر عنوان وسياق مفهوم مع إلغاء/إغلاق يعمل، ثم تستقر البطاقات دون قفز مخطط الصفحة. إلغاء الطلب أو تغييره يمنع وصول نتيجة قديمة إلى جلسة أحدث.

## 6. وصف المجموعة والبطاقة

`DeckDescriptor` يحمل: groupId، مراجعة المحتوى إن وجدت، title، سبب العرض، sourceRefs، origin، وقائمة CardDescriptor. descriptor قابل للتسلسل؛ لا ReactNode أو callbacks أو HTML عشوائي قادم من البيانات. قارئ React يبنى من نوع البطاقة وبياناتها المعتمدة داخل renderer معلوم.

`CardDescriptor` يحمل: cardId ثابت، kind محدد، ContentRef، title/summary، reference للتفاصيل أو payload محدود بحسب المصدر، review label، allowedActions، وبديل نصي. يمكن أن يبقى تركيب البطاقة الحالية كما هو مع adapter رقيق؛ لا تعمم كل شيء قبل استخدامه.

الأنواع الحالية principle/caveat/evidence تظل دقيقة. إضافة comparison أو experiment لاحقًا تعني: عقد typed + renderer صريح + مصدر علمي + بديل نصي + قواعد إتاحة + اختبارات خاصة بمعناه. لا تجعل `kind: string` طريقًا لتجاوز صحة البيانات. النوع غير المدعوم يعرض ملخصًا مسموحًا ورابطًا أو رسالة واضحة؛ لا يسقط صامتًا.

الأفعال أمثلة typed: فتح مورد داخلي، فتح مصدر خارجي، تحديد موضع في الأطلس، انتقال لمحرك تدريب أصلي. تُتحقق الوجهة ويظهر نوعها. لا arbitrary onclick أو URL بروتوكوله غير مسموح. زر «اختبر نفسك» لا يصبح محرك تصحيح داخل Dealer دون مهمة محددة.

الحالة المرئية deck/hand/reader منفصلة عن حالة المادة العلمية. نقل ورقة إلى اليد لا يعني أنها قُرئت، وجمع اليد لا يعني حذف تقدم، وإغلاق القارئ لا يعني حل السؤال.

## 7. الأهلية أربع قدرات مستقلة

| القدرة | مصدر القرار | مثال قبول أو منع |
|---|---|---|
| discover | سياسة عرض المصدر والفهرس العام | إظهار عنوان مورد ورابطه |
| readFull | حقوق وسياسة نشر النص الأصلي | LINK_ONLY يسمح وصفًا/رابطًا؛ لا نسخ النص الكامل |
| assess | محرك التدريب وحالة المراجعة للسؤال | HOLD يبقى غير قابل للتصحيح ولو ظهر في مكتبة مراجعة |
| relate | الإسقاط المنشور لعلاقات Atlas | وجود المورد في كتالوج موضوع لا ينشر مفهومه أو سهمًا علميًا |

هذه القدرات لا تستنتج من `StudyRecord.status` النصي أو من وجود href. مثال فعلي يجب ألا يُنسى: إدراج بعض insights في `study/server.ts` يرث base.status لدرس؛ resolver الخاص بها يجب أن يقرأ `insight.reviewStatus` وسياسة eligibleInsights مباشرة.

تحقق وقت تجهيز البيانات قبل serialization. إخفاء زر في المتصفح ليس حماية كافية إذا كانت المادة غير المؤهلة سُلسلت إلى الصفحة أصلًا. أسئلة R11 الموقوفة لا تنتقل إلى بطاقات مصححة، ومعاينات الأفكار تظل معاينات، والروابط المرجعية تبقى وفق حقوقها.

Home يستعمل إسقاط Atlas عامًّا صريحًا. اختبر تغير `HANSA_ATLAS_REVIEW_PREVIEW` حتى لا يتسرب draft من البيئة. لا توسّع allowlist المصادر العلمية أو روابط DP-600 القديمة بتعبير يسمح بأي URL؛ الفهرس العام له قواعد مستقلة محددة.

## 8. ملكية الحالة والتخزين والعودة

| الحالة | المالك | قواعدها |
|---|---|---|
| edition/scope/selection المهمة للمشاركة | URL serializer موحد | push لقرار مقصود؛ replace للتصحيح؛ لا كتابة لكل hover/scroll |
| حزمة اليوم والورقة والقارئ | جلسة Dealer في الزيارة | مفتاح من origin/هوية المجموعة؛ تبديل المصدر لا يخلط حالتين |
| الفروع وسياق العودة | حالة أطلس/جلسة متصفح محدودة | الرجوع حسب ID؛ تعاد هندسة الموضع عند resize |
| نتائج ومحاولات التدريب | المحرك الأصلي | Home لا يكتب إليها |
| حفظ مجموعة عبر الزيارات | ميزة لاحقة مستقلة | schema version ومفتاح جديد وحدود حجم وحالات فساد/ترحيل |

لا تدمج `amir-lab-v1`, `amir-fabric-v1`, additions/R11/Academy/Atlas journey في مخزن واحد. adapter التقدم يعيد begun/completed/result/unknown بحسب المعنى الأصلي. عدم وجود سجل ليس صفر إتقان. لا نسبة إتقان عامة تجمع مقاييس غير متجانسة.

العقد الحالي لـ`atlasReturn` مقيد بـDP-600؛ احفظ معناه وروابطه. أضف عودة Home بعقد مستقل أو امتداد متوافق بعد فحص كل caller. اسمح بالroutes الداخلية المطابقة للفهرس وبأطوال معقولة، ورفض بروتوكولات/hosts غير مصرح بها. query غير صالح يعيد لوالد صالح برسالة، لا لمسار خارجي.

عندما تُنفذ ميزة حفظ المجموعة لاحقًا: أعد resolve المحتوى عند الاستئناف، وقارن مراجعاته، واستعد البطاقات الصالحة وأبلغ بالمادة التي تغيرت أو سُحبت. لا تعيد عرض payload قديم لتجاوز المراجعة الحالية، ولا تحذف نتائج التعلم القديمة لمعالجة تغير العرض. لا تُنفذ storage migration احتياطيًا في هذه المرحلة.

## 9. التوسع البصري والحركة

نفس المفردات تخدم الإضافات: التحديد يوضح العنصر، والفتح يكشف التفاصيل، والانتقال يحتفظ بالمرجع، والعودة تستعيده. طريقة تجهيز المجموعة لا تحتوي مدد animation أو قياسات viewport. طبقة الحركة تقرأ الحالة ولا تقرر عضوية المحتوى.

الـvignette ونظام توزيع البوابات يعملان عند تغير عدد المجالات؛ العدد8 وصف للحالة الحالية، لا شرط layout دائم. عند كثافة كبيرة انتقل إلى تجمعات/صفحات/قائمة/بحث بحسب التصميم، مع بقاء الوصول الكامل. لا تضع إحداثيات مطلقة لكل درس في كود Home.

نوع البطاقة يحدد قيود العرض والبديل، بينما قواعد الإغلاق والتركيز والعودة واحدة. تجربة تحتاج تفاعلًا أكثر تعيش في reader أو وجهتها، لا داخل وجه بطاقة صغير مزدحم. طبقة العرض المستقبلية لا تحمل كل renderers في bundle البداية؛ imports ثابتة ومحللة مع تحميل عند الحاجة.

الموبايل/reduced-motion هما استراتيجيتا عرض لنفس الحالة والمحتوى. لا تبنِ مسار بيانات أو تقدم منفصلًا لكل جهاز. وضع قائمة الأطلس يظل شريكًا وظيفيًا للخريطة في كل إضافة.

## 10. إثبات الاستعداد دون بناء كل المستقبل

| ID | فحص صغير قابل للتنفيذ | ما يثبته |
|---|---|---|
| E01 | جهّز عينة Topic Deck من مادة حقيقية عبر adapter تطوير غير منشور | يمكن توصيل مصدر جديد دون تعديل shell المشاهد أو هندسة Dealer |
| E02 | افتح العينة من موضوع، افتح موردًا ثم ارجع وغير عرض الشاشة | استعادة الموضوع والفرع والبطاقة بالهوية، لا بإحداثيات ثابتة |
| E03 | غيّر أهلية مورد في fixture بين resolve وإعادة الفتح | عرض حالة تغير مفهومة وحجب المادة غير المؤهلة دون مساس بالتقدم |
| E04 | اختبر kind غير مدعوم، LINK_ONLY، سؤال HOLD، مفهوم غير منشور | fallback صحيح؛ القدرات مستقلة ولا تجاوز للمراجعة |
| E05 | أضف موردًا أو مجالًا تجريبيًا موسومًا في بيانات الاختبار فقط | الفهرس والبحث والتغطية والتكوين لا تعتمد على العدد8 أو شروط يدوية لكل درس |

اختباراتE01–E06 تُثبت العقود الموجودة في التسليم بأقل عينة لازمة. لا تستدعي تشغيل future features عامة، أو كتابة اختبارات لتكرار implementation، أو بناء تخزين دائم غير مطلوب. ترحيل مجموعات محفوظة اختبار لاحق عندما يُطلب الحفظ نفسه.

## 11. ما لا يندرج تلقائيًا ضمن المستقبل المطلوب

الحسابات، المزامنة السحابية، backend مدفوع، مولد بطاقات بالذكاء الاصطناعي، جدولة تكرار متباعد، readiness score، CMS، تخصيص تنبؤي أو 3D ليست جزءًا لازمًا من هذا التسليم. إذا طُلبت لاحقًا، تُراجع كمهام لها مصادر وخصوصية وتكلفة وقياس مستقل. لا تبنِ اعتمادًا عليها في core الصفحة.

## 12. أدلة المستودع التي تُراجع عند التنفيذ

- `components/knowledge/knowledge-dealer.tsx`: عرض قابل لتزويده بـcards/reader/callbacks.
- `lib/knowledge/models.ts`: CardKind وinsightCards وcardBody الحالية.
- `lib/knowledge/insights.ts`: أهلية الإصدارات وحدود preview.
- `lib/study/taxonomy.ts`: StudyRecord والوصف النصي للحالة.
- `lib/study/server.ts`: تجميع المصادر وإدراج الأفكار.
- `lib/atlas/model.ts`: بوابات النشر والعلاقات والروابط وعودة DP-600.
- `lib/atlas/server.ts`: تأثير متغير بيئة المعاينة.
- `lib/site.ts`: canonical/alias/navigation المشتركة.

معيار النجاح النهائي لهذا الملحق: يمكن شرح مكان إضافة مصدر بطاقات أو نوع بطاقة أو موضع دخول جديد، وإثباته بعينة محدودة، مع استمرار نفس قواعد الهوية والأهلية والتركيز والعودة والتقدم.
