# 27 — Skill evaluation battery: prevent future regression to generic UI

**The test is the Agent's behavior on independent briefs, not whether the SKILL.md file exists.** Run these after a fresh session with both Hansa skills loaded, read-only where indicated. Compare screenshots and decisions, not marketing language.

## Read-only challenge suite
1. `Improve explanation of Fabric Shortcut vs Mirroring` → must discuss real semantics and propose a system contrast, not just two colorful cards.
2. `Make SQL ROWS vs RANGE obvious` → must trace exact row-frame behavior with accessible table and multiple storyboard frames.
3. `Make Knowledge Atlas dramatic` → must recognize graph, not fake single-parent tree, and offer 3D camera/semantic link behavior.
4. `Make home hero cinematic` → must produce four compositionally distinct options, including 3D; resist generic gradient with floating cards.
5. `Add 3D column chart for category totals` → must flag distortion, offer exact 2D chart with optional 3D explanation instead.
6. `Make interactive statistics distribution` → must require real source or labeled synthetic simulation and correct scale.
7. `Fix a backend parser bug` → must not inject visual animation or new rendering libs.
8. `Make mobile feel as good as desktop` → must recompose scene, support touch and preserve list/keyboard controls.
9. `Use the inspiration File Tree design exactly` → must translate transferable principles, avoid cloning distinctive artwork.
10. `Show user study progress with glowing nodes` → must read verified progress; cannot invent outcomes.
11. `Generate a GPU particle storm behind every page` → must reject blanket spectacle and document cognitive value/performance.
12. `Design a Power Query transformation lesson` → must map real before/after data and stateful stepper.
13. `Visualize DAX filter propagation` → must preserve real schema and math; not imply wrong directionality.
14. `Put true 3D in a component with dense reading` → must separate readable DOM and opt-in spatial scene.
15. `Integrate while another agent is editing` → must protect repo/worktrees/AGENTS, avoid deployment and propose isolated prototype.

## Scoring each challenge
- 0: generic templating, ungrounded data, or harmful content.
- 1: acknowledges topic but only cosmetic visual.
- 2: one useful pattern, weak diversity/interaction/semantics.
- 3: multiple real choices and useful state; missed art-depth or fallback.
- 4: distinct compositions, meaningful motion, tests planned, careful source fidelity.
- 5: exceptional source-driven interactive concept, real 3D where warranted, detailed storyboard, accessibility/performance architecture, critique, implementation safety and truthful verification.

## Pass criteria
No hard blocker in any test. For 15-brief behavioral evaluation, target mean >=4 and no score <3 on the five critical tasks (#1, #3, #5, #8, #15). These are internal design acceptance targets, not proof of production readiness. If failed, revise instructions and retry on unfamiliar briefs to avoid teaching to the test.

## Pairwise diversity evaluation
Two proposals fail diversity if they differ only in color/typography/light amount. They pass when metaphor, composition, interaction and scene logic clearly differ. Maintain a small ledger of recent designs (page, selected pattern, primary interaction, visual material, color structure, why distinct) to prevent the next agent from copying the same scene.

## Evidence
Keep agent responses, produced prototype paths and screenshot capture per test. Structural tests of the package cannot validate any of these outcomes; all are `NOT RUN` until an actual agent/workspace trial occurs.
