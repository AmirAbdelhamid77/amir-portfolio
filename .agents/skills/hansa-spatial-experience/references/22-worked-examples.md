# 22 — Fully worked experience briefs

## Case 1 — Living OneLake Knowledge Atlas (real typed graph)
**Goal:** users explore relationship types without treating semantic graph as tree.
**Source:** canonical concepts/typed edges and citations; inspect current QA status and preserve IDs.
**Composition:** central focus sculpture with organic illuminated links to nearby concept volumes; far background suggests remaining context. Camera remains mostly anchored; selecting related concept causes focused translation, not disorienting spin. DOM inspector always displays exact concept text/source and all edges.
**Visual states:** intro overview; search highlight; selected; edge-type filter; relation reveal; recent selection/history; reset; fallback list.
**Interaction:** pointer hit, visible focusable list, Enter select, touch tap, camera zoom buttons, Escape details close; list and scene stay synced.
**Tech:** R3F if true spatial version approved; SVG 2.5D alternative must be built for comparison. D3 may compute 2D/3D-independent graph positions, not define source truth. Use deterministic node placement and stable edge identifiers.
**Motion:** connection filaments grow only for selected verified edges; unrelated edges dim; camera gently reframes with interruption; reduced-motion instantly changes focus.
**Test:** verify no invented edge, graph cycles/multiple parents handled, 80+ node stress fixture labeled synthetic, 320px DOM list, semantic relationship labels and fallback.

## Case 2 — DP-600 Shortcut vs Mirroring Decision Theatre
**Goal:** explain distinctions without claiming wrong data movement.
**Composition:** two synchronized miniature system stages: a connection reference path and a replication path; comparative text/status table pinned in DOM. Animate click-through on actual scenario choices.
**Mapping:** source-backed descriptions determine each stage and label; no claim that moving glow particle accurately models sync frequency or size. Choice selects an explicit explanation, not automatic answer grading without approved key.
**Motion:** paths illuminate in sequence as user navigates stages, with pause, replay, reset.
**3D value:** architecture layering/volumetric systems helps orient sources and destinations, but precise facts stay in readable text. 2.5D SVG alternative provided.
**Test:** real text consistency; if scientific approval pending, `review_pending` communicated and no verified correct marker.

## Case 3 — SQL Window Function Execution Microscope
**Goal:** build a correct mental model of PARTITION, ORDER, ROWS/RANGE frames.
**Composition:** each row is a physical slab on a table-like stage, partitions are visually separated lanes, current frame highlighted via controlled camera detail. Exact source table and computed results remain visible in DOM.
**States:** dataset baseline; partition; order; frame start/end; aggregation; output. A stepper and slider navigate same computed states; formula and sample rows verified.
**3D value:** layer/sequence orientation; but large datasets collapse to precise tabular mode. Avoid random row motion that suggests wrong order.
**Test:** snapshot exact rows for 2–3 independent cases, keyboard stepper, narrow-screen table-first fallback.

## Case 5 — Statistics Uncertainty Observatory
**Goal:** explain statistical uncertainty without misleading encoding.
**Composition:** authoritative 2D interval/point chart in DOM/SVG, optional 3D sculpture illustrates sampling mechanism (not claims about a real study). Visual intensity is secondary to exact units and explanation.
**States:** source dataset or explicitly labeled synthetic simulation, parameter changes with deterministic seed and displayed assumptions, confidence level labels; display exact numeric outcomes.
**Motion:** samples settle and interval updates smoothly; no continuous random drift once actual estimate is shown.
**Test:** recompute calculations independently, read labels at mobile, reduced-motion fixed frames, no implied z-axis in exact chart.
