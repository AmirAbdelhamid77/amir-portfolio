# 15 — Divergent creative prototype lab

## Independent lab
Use a separate scratch workspace or a new worktree only after checking that no concurrent files will be altered. When the owner asks only for a skill, DO NOT build a live Hansa page. Prototype tasks require their own instruction/approval; here the skill documents future process.

## Experiment design
Start with a one-page problem brief, canonical sample data, success criteria and device targets. Present A/B/C/D with divergent scene metaphor/composition. Reduce to two interactive candidates based on source-meaning, distinctive staging and hardware cost; build both before polishing one.

## Candidate A — Architectural 2.5D
Layered planes, strong type, controlled camera-like pan, precise DOM controls. Strength: performance and literacy; weakness: limited volumetric manipulation.

## Candidate B — True Spatial 3D
R3F/Three 3D camera, objects with depth, focus travel and occlusion, real manipulable scene. Strength: spatial mechanics and memorable material; weakness: GPU and a11y overhead.

## Candidate C — Organic Procedural
Growth curves, filaments, instanced points and articulated relationships. Strength: metaphor and discovery; weakness: dense information can become tangled.

## Candidate D — Cinematic Editorial
Scroll-scrubbed narrative and typographic installations; strong storytelling and accessible content. Weakness: less freeform discovery.

## Test matrix
1. First 3 seconds: can user perceive one dominant idea?
2. First action: is affordance obvious and response meaningful?
3. Fifth action: is orientation still clear? Is reset possible?
4. Dense realistic content: can design survive more nodes/long labels?
5. Performance on midrange/low-end device; if no device test, flag NOT RUN.
6. Mobile transformation vs shrunk desktop.
7. Reduced motion still teaches same material.

## Iteration cadence
V0 wire + frames; V1 interactive prototype; V2 layout/craft; V3 accessibility/performance; V4 approved integration proposal. User can choose without waiting for unnecessary overengineering. Any library installation or production merge is a separate explicit decision.
