# Contextual experiences — inspiration, not mandated templates

Each idea is a candidate. Inspect actual Hansa source, content evidence, AGENTS.md, current implementation and working agent diff before using it. No scenario is authorization to edit unrelated work.

## Prototype C landing / Contextual Hybrid

- **Daily Insight Timeline:** editorial evidence-based "insight beat" with inspectable provenance; user-triggered reveal/dive, not generic fake statistics or autoplay cards. Consider nested time context only if source has dates.
- **Card Dealer:** an intentional content chooser with depth/staging, keyboard and touch navigation, stable page destinations, content preview and learning path progression. Do not imitate casino mechanics or obstruct navigation.
- **Knowledge Atlas peek:** circular concept constellation with true links to learning nodes, animated selection and focus. Clear transition to full explorer; avoid showing invented relations.
- **Narrative integration:** these experiences should look related but not identical; distinct motion grammars and different information tasks.

## Microsoft Fabric / DP-600

- **Trace data:** real/illustrative source → ingestion → OneLake → Delta table / Warehouse / semantic model. Stages clickable; animated record trace mirrors an *explicit documented* transformation. A source-backed description appears when a stage is selected.
- **Compare Mirroring vs Shortcut vs Copy:** two/three synchronized scenarios show actual distinctions; interactive decision constraints; no fake bandwidth/latency claims.
- **Delta transactions:** precise sequence (file writes, log commits, versions, vacuum caveats) with step controls and provenance.
- **Exam scenario:** show case structure and evidence; keep QA-blocked answers ungraded and distinct from source keys.

## SQL / Window Functions

- Show base data rows; partition/sort steps; frame window; running total or ranking results. Changing ORDER BY/PARTITION BY recomputes results using a trusted deterministic example. Animation moves a focus bracket and updates exact rows, not fabricated query execution.
- DAX filter context: render a dependency trace/propagation diagram and measure evaluation state when there is verified model logic.

## Statistics / Data Visualization

- Histograms with interactive bin counts from a fixed dataset; explain how binning changes shape, not underlying observations.
- Mean/variance or confidence intervals recomputed from explicitly labeled parameters; show formulas and underlying numbers, no fake empirical generalization.
- Graph of misleading truncated axis: same data and truthful baseline warning; toggle reveals the visual distortion. Comparison stays interpretable without transitions.
- Cross-filter chart design: link a chart and table, with keyboard-selectable series and evidence-backed filters; don't assume every chart type is appropriate.

## Knowledge Atlas

- Semantic graph with stable node/edge IDs; circular responsive concepts. On focus/tap/click: selected circle emphasis + edge highlight + nearby relationship explanation and source link. Pan/zoom with accessible controls; responsive focused-list view on mobile.
- Cross-domain Knowledge Atlas is distinct from existing Statistics Atlas route. Preserve separate concepts and progress stores.
- Unknown graph edge → exclude/flag as unverified, not a decorative dotted line interpreted as "related".

## Data Storytelling / References

- Scroll or explicit step control reveals annotated story beats; user can inspect underlying chart and supporting data without being forced through animation.
- Reference-heavy topics remain easy to scan/search/copy; selectively enrich hard-to-understand mechanisms with a single strong visual instead of turning every reference note into a carousel.

## Visual micro-brief examples

**Strong:** "The learner can predict how `PARTITION BY` splits the same rows before seeing the running total; the partition colors and numbers remain stable through the transition."

**Weak:** "Use D3 to create a futuristic interactive SQL interface." (No specified data semantics, state, lesson, or correctness criterion.)

**Strong:** "Select a concept in Atlas; only verified prerequisite edges are illuminated; all neighboring IDs are stable; the details panel explains what the link means."

**Weak:** "Make a floating glowing network with hundreds of particles." (No evidence or learning value.)
