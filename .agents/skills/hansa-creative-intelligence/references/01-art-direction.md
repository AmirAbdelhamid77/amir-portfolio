# Art direction: adaptive, expressive, never the same template

## Hansa design compass

- **Identity:** a living knowledge space about analytics, not a generic SaaS admin template. Serious data semantics with a sense of discovery and expressive motion.
- **Contrast:** informational precision against exploratory visuals; technical credibility against selective expressive staging; disciplined hierarchy against controlled surprise.
- **Experience:** visitors should know *where they are*, *what they can do*, *what changed*, and *what the graphic teaches*.
- **Continuity:** keep the existing brand tokens, typography, CSS architecture, responsive patterns and content hierarchy. Innovate in **composition and visual storytelling**, not by replacing established foundations arbitrarily.

## The Visual Opportunity Pass

Before choosing markup, produce 3 mental sketches with substantially different compositions. At least one should abandon the default card-grid solution. For a significant page, sketch/state these three in the task log:

1. **Editorial clarity:** strong typographic anchor, annotated data or precise diagram, selective emphasis, generous negative space.
2. **Explorable system:** spatial graph, connected nodes, layered interactive chart, simulation surface, or step-wise process, with user-controlled states.
3. **Narrative motion:** scene progression tied to evidence and scrolling **without hijacking scroll**, staged transformations, before/after states, chapter transitions.

Pick the one that carries the concept. Combine two carefully only if each adds meaning; avoid a buffet of simultaneous widgets.

## Techniques for visual depth

- **Layering:** deliberate foreground/midground/background; use subtle overlays, pseudo-depth, occlusion, depth-of-field only when legibility remains intact.
- **Topology:** a visual "spine" connecting concepts, decisions or timeline events can unify a page better than isolated rectangles.
- **Progression:** start with an intelligible overview, invite focus, then reveal detail. Animate graph changes in stages to preserve the user's mental map.
- **Shape language:** variable-radius circles/clusters for relational concepts and hubs; ribbons/lines for quantitative flows; traces for transformations; strict grids for precise comparison; sloped editorial crops where appropriate.
- **Lighting/material:** restrained highlight, shadow and edge treatment to signal selection or hierarchy. Don't reproduce glow around every clickable element.
- **Typography-as-composition:** meaningful line breaks, large analytical statements, editorial rhythm; not giant isolated buzzwords.
- **Responsive reinterpretation:** Desktop spatial canvas may become swipe/focus-selected journey or vertical relationship explorer on small screens; don't scale an unreadable graph to phone width.

## Choose a signature per experience

Write down one project-specific, falsifiable differentiator, for example:
- "The network reorganizes around the selected Fabric concept, while evidence-backed neighbors glow only when selected."
- "The same input rows literally flow through the SQL pipeline; every transformation changes the visible result table."
- "The distribution's confidence interval shrinks as sample size grows; its interval bounds are recomputed, not visually faked."

Reject vague statements such as "beautiful modern design," "lots of animation," or "add hover effects." Shape each signature around data, concept, user action and feedback.

## Motion restraint: purpose beats spectacle

Every animated movement should make at least one thing easier to understand:
- Which element entered / exited / changed?
- Which transformation produced the output?
- Which concept is related to the selected node?
- How did the axes, filters, or uncertainty change?

Decorative ambient motion can be appropriate in a contained hero but must not interfere with study, text clarity, reduced motion, or performance. Do not make every page cinematic; choose where the contrast is most effective.

## Owner decisions to preserve

- Prototype C / Contextual Hybrid is an approved direction for landing-page exploration; the agent must **inspect the current version before designing** and must not revert to an earlier flat prototype.
- Daily Insight Timeline, Card Dealer and Knowledge Atlas are concepts with different interactions and must not become three identical cards with different headings.
- Knowledge Atlas has a deliberate preference for responsive, clickable/hoverable circular nodes; semantic edges only. Don't confuse the cross-domain Knowledge Atlas with the separate Statistics Atlas.
- DP-600 Academy and learning references have stronger priority than the legacy HSE section. Avoid promoting HSE as Hansa's flagship without a current request.

## Creative critique prompts

- Could this be swapped into a generic dashboard without anyone noticing? If yes, innovate.
- Is the main insight visually discoverable in the first few seconds? If no, simplify hierarchy.
- Does the layout still feel authored when the animation is switched off? If no, motion is covering weak composition.
- Have I animated a meaningful relation/data change rather than only fade-in and scale-up? If no, add a proper state transition if justified.
- Does the mobile version express the same concept, not merely hide the interesting part? If no, redesign the responsive model.
